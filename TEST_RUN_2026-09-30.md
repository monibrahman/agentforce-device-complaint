# Test run and fixes: 2026-09-30

Claude Code ran these tests automatically as a pair programmer. Each conversation was a scripted `sf agent preview` session (`start` / `send` / `end`) against the published, active agent in the `complaints` org, with real Apex actions and the real openFDA callout. Each conversation was checked three ways:

1. **Transcript**: what the customer saw.
2. **Trace** (`.sfdx/agents/<agentId>/sessions/<sessionId>/traces/`): which subagent handled each turn, which actions ran, and which variables were set.
3. **Case record** (`sf data query`): priority, queue, harm flags and complaint fields, wherever a case was created.

For the full root cause, fix and lesson behind each bug, see [docs/BUILD_LOG.md](docs/BUILD_LOG.md).

## Changes made

| Commit | Change | Why |
| --- | --- | --- |
| `a2d5784` | **Router continuity (Open Gate pattern).** New `open_gate` variable. Intake and escalation set it with a procedural `set`. The router checks it with a conditional `transition to` before its LLM reasons. It is cleared in `after_reasoning` once the case exists. Also: the router must always call exactly one tool; intake must save details before replying; the harm question comes first; at most two questions. New system rule: never say a complaint is logged without a complaint number. Design decision 7 added to [docs/DESIGN.md](docs/DESIGN.md). | Live test 1 lost a complaint. On turn 2 the router LLM replied to the customer's details itself instead of routing them, so intake, the harm screen and case creation never ran, and the agent claimed the report "will be recorded". |
| `05b13dd` | `deploy.ps1` and `deploy.sh` now run `sf agent activate --json`. | The CLI now shows an interactive version picker, which stopped the deploy script after a successful publish. |
| `43d92ad` | Intake saves only details the customer actually gave. It estimates only from a rough date the customer offers, and otherwise asks. | A trace showed intake saving today's date on turn 1 when the customer hadn't given a date. |
| `fb5b070` | The escalation save action (`save_contact_details`, now `save_escalation_details`) accepts manufacturer, lot/serial and event date. Escalation asks for them, as optional, alongside the contact details. | Urgent case 00001029 was created with manufacturer, lot and date empty, even though the customer had mentioned them. |

Agent versions: v4 had the routing fix, v5 the date fix, v6 the escalation fix (active now).

## Open items

- **Test 9:** platform guardrails can drop a real complaint that's embedded in an adversarial message. Needs a design decision.
- **Test 10:** not yet run.
- The first escalation reply lists about five things to provide, which bends the two-question rule.
- Details the customer gives after a case is created can't be added to it. Production would add an "update case" action.
- Intake once said "I've recorded that…" before any case existed. It referred to the details, not the complaint, but could be misread.
- Test 1b asks for the complaint number again right after giving it.
- The "Open bug (fix this first)" section in `CLAUDE.md` is stale.
- The replay script used for these runs lives outside the repo. Turning these cases into an `sf agent test` suite in `specs/` is the next step.
